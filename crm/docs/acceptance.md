# Приёмка

## Функциональные сценарии

- Войти постановщиком. Создать объект, изменить название/адрес, создать задачу и назначить исполнителя.
- Войти исполнителем 1. Видны только его задачи и связанные объекты; кнопок редактирования и удаления нет.
- Пройти «Новая → В работе → На проверке». Проверить автора и время в истории.
- Войти постановщиком. Возврат без комментария запрещён. Вернуть с комментарием.
- Войти исполнителем 1. Увидеть комментарий, повторно взять в работу и отправить на проверку.
- Принять постановщиком. Из принятой задачи переходов нет.
- Войти исполнителем 2. Чужая задача по скопированной ссылке недоступна.
- Переназначить задачу. Прежний исполнитель после обновления теряет доступ, новый получает.
- Проверить отмену удаления, а затем удаление специально созданного временного объекта/задачи.
- Проверить поиск, фильтр статуса, обновление страницы по прямой ссылке, выход и повторный вход, узкую ширину окна.

## Безопасность

- `npm test`: 10 тестов, включая 50 комбинаций переходов.
- Напрямую через Supabase REST: чужая задача и история не возвращаются, PATCH задачи/профиля, INSERT/DELETE истории запрещены.
- RPC перехода чужой задачи и недопустимый переход возвращают ошибку.
- GET `/auth/v1/settings`: `disable_signup: true`; публичный signUp не создаёт учётную запись.
- Во фронтенде и Git нет service_role, PAT или тестовых паролей.

Проверки SQL автоматизированы в `tests/security.test.mjs`. Облачные проверки выполняются после установки миграции и создания пользователей. Итоговые результаты фиксируются в сообщении сдачи, без утверждения о непроведённых проверках.
