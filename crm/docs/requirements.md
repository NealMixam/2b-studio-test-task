# Требования и план проверки

Источник: PDF задания в корне репозитория.

- React + TypeScript, Supabase Auth (email/пароль), PostgreSQL.
- Несколько постановщиков и исполнителей. Постановщики видят всё; исполнители — свои задачи и связанные объекты.
- Создание, изменение, удаление объектов и задач постановщиками.
- Назначение только исполнителя. Автор и дата создания определяются базой.
- Новая → В работе → На проверке → Принята / На доработке → В работе.
- Возврат требует непустого комментария. Другие переходы запрещены в базе.
- История: автор действия, время, старый и новый статус, комментарий. Запись в одной транзакции со сменой статуса.
- Пять экранов: вход, объекты, объект, задача, мои задачи.
- RLS, отсутствие прямой записи в таблицы через API, ограниченные RPC, закрытая регистрация.
- Минимум 1 постановщик, 2 исполнителя, 3 объекта, задачи в разных статусах.
- Миграции, README, объяснение руководителю, решения/допущения, инструкция сдачи.
- Проверки напрямую в PostgreSQL: изоляция пользователей, все пары переходов, запрет подделки истории и роли, CRUD, обязательный комментарий.
- Публикация и GitHub требуют доступа к внешним аккаунтам. Отправка сообщения работодателю выполняется пользователем.

Этапы коммитов: каркас; база и безопасность; интерфейс; проверки и документация; публикация при наличии доступов.
