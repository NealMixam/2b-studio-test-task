# Повторный аудит безопасности

11 ноября 2026 года. Проверены исходники, SQL, история Git, production-сборка и живой Supabase HTTP API. Это ограниченная техническая проверка приложения, а не полный пентест инфраструктуры или личного аккаунта владельца.

## Найдено и исправлено

1. PostgreSQL `trim()` убирал обычные пробелы, но оставлял табуляции и переводы строк. Через прямой RPC можно было вернуть задачу с визуально пустым комментарием. Во второй миграции триггер требует хотя бы один непробельный символ.
2. Передача `NULL` в `p_expected_status` обходила сравнение ожидаемого статуса из-за трёхзначной SQL-логики. Это не обходило роли или граф переходов, но ослабляло защиту от устаревшего запроса. Во второй миграции NULL отклоняется явно, сравнение выполнено через `IS DISTINCT FROM`.
3. Тестовый скрипт теперь завершает только собственную сессию (`scope: local`), чтобы повторные проверки не отзывали пользовательские сессии той же демонстрационной учётной записи.

Два новых регрессионных теста сначала воспроизвели ошибки на исходной миграции. После второй миграции все 10 тестов проходят. Исправления применены владельцем в облачной базе; прямой HTTP-тест обоих случаев также прошёл.

## Подтверждено проверками

- Анониму закрыто чтение каждой из четырёх таблиц.
- Исполнители изолированы по задачам, объектам и истории.
- Прямые записи в таблицы, изменение роли, создание и удаление истории через API запрещены.
- Постановщик CRM не имеет доступа к Supabase Auth Admin API (403).
- Схема `auth` не экспонируется через Data API (406).
- Поддельный JWT с ролью service_role отвергается (401).
- Триггерные функции нельзя напрямую вызвать через RPC.
- Открытая регистрация отключена. Все три демонстрационных пользователя могут войти.
- Доступный сайт отдаёт HTTP 200, его JS использует предоставленный Supabase-проект и только публичный ключ.
- Проверены все пять предыдущих коммитов (89 файлов/версий вместе со сборкой): тестовые пароли, PAT, secret key и service_role JWT не найдены. Локальные .env и .tmp не отслеживаются Git.
- С сайта не выдаются локальные .env и файл тестовых паролей.

## Личный аккаунт Supabase

Приложение не содержит пароль владельца, Personal Access Token, service_role или secret key. Файл `.env.deploy` не создавался. SQL выполнял владелец через SQL Editor. Участники организации, настройки биллинга и ключи аккаунта приложением не изменялись.

Публичный ключ предназначен для браузера и не даёт входа в личный кабинет. Учётные записи CRM созданы внутри проекта Supabase Auth и не являются участниками Supabase-организации. Даже роль manager даёт права только в этой CRM.

MFA владельца, список активных сессий, существующие сторонние PAT/интеграции и участники организации не проверялись: административного доступа для этого не было. Поэтому утверждения о полной безопасности личного аккаунта не делаются. Для личного кабинета рекомендуется MFA и проверка списка выданных токенов/участников.

## Оставшиеся ограничения

- Проверка браузерного интерфейса/скриншотов не завершена из-за сбоев инструмента. SQL, Auth, REST и публикация проверены отдельно.
- В проверенном ответе хостинга отсутствуют CSP, X-Frame-Options и HSTS. Это направления дополнительного усиления публичного production-хостинга, а не обнаруженный способ войти в аккаунт Supabase. React выводит пользовательский текст с экранированием; опасные HTML-вставки не используются.
- Сессия SPA хранится стандартным Supabase-клиентом в браузере; защита от XSS остаётся существенной. Для реальной эксплуатации следует добавить CSP/защиту от встраивания, MFA для привилегированных пользователей и эксплуатационный мониторинг.
- Пароли демонстрации находятся в локальной `.tmp` в открытом виде для передачи проверяющему. Не публиковать папку, SQL установки и файл сообщения с паролями. Доступ постановщика разрешает удалять данные CRM, поэтому передавать его только проверяющему.
- Удаление задачи/объекта постановщиком удаляет историю каскадно. Отдельное редактирование истории закрыто; постоянный юридический архив не реализован (см. решения и допущения).

Источники: https://supabase.com/docs/guides/getting-started/api-keys и https://supabase.com/docs/guides/platform/multi-factor-authentication.
